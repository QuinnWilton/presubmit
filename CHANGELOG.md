# Changelog

## Unreleased

### Added

- `mix presubmit`: runs the rule sets in `.presubmit.exs` (or every built-in set by default) against a change set and reports each rule as passed, failed, or skipped. Sources: `--head`, `--rev`, `--staged`, `--worktree`, `--range A..B`; the default is the working tree when anything differs from `HEAD`, else `HEAD`, and the first line of output always names what was examined. `--format json`, `--list`, and a warning when a dirty working tree is examined under `CI`.
- `mix presubmit.install` writes `prepare-commit-msg` and `commit-msg` hooks (and, with `--pre-commit`, a `pre-commit` hook) that run the policy on the staged changes and the message; when the commit amends `HEAD`, the amended commit (`HEAD^` to the index) is checked rather than the delta. `--uninstall` removes them; a hook it did not write is never overwritten (`Presubmit.Hooks`).
- `--base REV` measures a `--staged` or `--worktree` change set against `REV` instead of `HEAD` (`Commit.staged/1` and `worktree/1` take `base:`).
- `--message-file PATH` / `--message TEXT` attach a commit message to a `--staged` or `--worktree` change set so message rules run from a `commit-msg` hook; comment and scissors lines are stripped as git does (`Message.clean/1`, `Presubmit.load/1` `message:`).
- Detection-aware defaults: rule sets declare `requires:` (`use Presubmit.RuleSet, requires: [{:phoenix, Phoenix.Router}]`); without a `.presubmit.exs`, `Presubmit.Config.default/1` enables `Rules.Phoenix`/`Rules.Ecto` when the library is loaded in the VM or is a declared or locked dependency of the examined tree, and `Rules.Changelog` when `CHANGELOG.md` exists. The output names what was enabled and why (`Presubmit.RuleSet.applicable?/2`, `Presubmit.Config.env/1`, JSON `config`).
- `Query.behaviour_changed?/2` and `function_changes/2` take a path pattern; `behaviour_changes_tested` is scoped to `lib/`, so a migration or script no longer demands a test change.
- Rule sets: `Presubmit.RuleSet` (`use` + `rule/3`) and built-in `Rules.Elixir`, `Rules.Phoenix`, `Rules.Ecto`, `Rules.OTP`, `Rules.ExUnit`, `Rules.Mix`, `Rules.Changelog`, `Rules.Message`, `Rules.Hygiene`, `Rules.Shape`, with `only:`/`except:` and per-set options.
- Change sources: `Commit.worktree/1` (via a temporary index, never touching the real one) and `Presubmit.load/1` with `source: :auto`.
- Structural source layer: `Presubmit.Source.Facts` (per-file modules, functions, attributes, struct fields, alias-resolved references), `Presubmit.Source.Diff` (modules and functions added/removed/renamed/changed, `behaviour_changed?/1`), `Presubmit.Source.Index`.
- Library-aware adapters implementing `Presubmit.Adapter`: `PhoenixRouter`, `PhoenixHandler`, `EctoSchema`, `EctoMigration`, `OtpProcess`, `ExUnitCase`; plus `Presubmit.MixFile` and `Presubmit.Changelog` parsers.
- Assertion verbs raising `Presubmit.Violation`: library-aware (`assert_routed`, `assert_migrations_ordered`, `assert_schema_changes_migrated`, `assert_supervised`, `assert_tested`, `assert_lock_in_sync`, `assert_api_changes_logged`, …), Elixir-source (`assert_specs`, `assert_moduledoc`, `assert_removals_deprecated`, `assert_pure_move`, `assert_references`), file, line, message, and shape.
- The facts cache is its own module, `Presubmit.Source.Cache`, so the concurrent protocol (table creation, owner death, bounding) is isolated and model-checked with Concuerror.
- Rules run in a plain linked worker instead of a `Task`; a worker killed from outside is reported as an error on the remaining rules rather than crashing the caller.
- A rule that exits or throws is reported as an error instead of crashing the run; a result sent by a worker in the instant before a timeout kill is flushed rather than left in the mailbox.
- The facts cache is keyed by blob *and* path: facts carry the path, so identical files at different paths must not share an entry (found by CI running tests in a different order).
- Rule sets document themselves: `use Presubmit.RuleSet` appends a "Rules" section (id, name, source/severity notes) to the set's `@moduledoc`.
- Commits can exempt themselves with `Presubmit-Skip: rule, rule` or `No-Presubmit: true` trailers (`Presubmit.Rule.exemptions/1`); the exemption is announced on every run, unlike `--no-verify`.
- Renamed from `assert_commit` to `presubmit` (`mix presubmit`, `.presubmit.exs`, `Presubmit.*`), after Chromium's presubmit checks, which this tool resembles far more than an ExUnit assertion library.
- Warning severity: `{Rules.X, warn: [:rule]}` (or `rule … severity: :warn`) reports a violation without failing the run (`⚠`, JSON status `warn`); `--warnings-as-errors` promotes them. The policy rules (`specs`, `removals_deprecated`, `api_changes_logged`, `behaviour_changes_tested`) are on by default as warnings.
- Scoping: `{Rules.X, in: pattern}` restricts a rule set to changes under a path (`Commit.restrict/2`); a set with no changes in scope is skipped. Together these mirror Chromium presubmit's severities and per-directory checks.
- Defaults calibrated on real histories: `specs`, `removals_deprecated`, `api_changes_logged`, and the `ExUnit` rules are opt-in; the defaults are the rules that do not fail an ordinary commit.
- `assert_pure_move` also rewrites moved files' paths in non-Elixir files, so moving a file and updating references to its path is a pure move (found on a real history: images moved, docs updated).
- Performance: facts are cached by blob object id in a shared ETS table (a range parses each file version once); `Tree.prefetch/2` bulk-reads paths with one `git archive` and is used for changed files, discovery, and `mix.exs` scanning; `mix.exs` files under `test/` are fixtures, not the project. A 300-commit range of the Elixir repository went from 5.5 minutes to about a minute; a single commit takes well under two seconds.
- Function clause identity expands aliases, so `alias A.B; B.f()` and `A.B.f()` are the same body and an alias-only refactor is not a behaviour change; `assert_pure_move` compares Elixir files through their facts with the rename map applied to resolved module names (`Facts.from_source/3` `renames:`). Property tests cover the change model, the JSON encoder, pure moves, and default-argument arities.
- Rules run in a worker process with a per-rule timeout (`--timeout SECS`, default 30); a rule that overruns is stopped and reported as an `Presubmit.RuleTimeoutError` while the rest still run.
- Hexdocs: README and CHANGELOG as extras, modules grouped; package description updated. README notes `import_deps: [:presubmit]` for the formatter and the trust model of `.presubmit.exs` under `--repo`.
- The facts cache lives in the calling process and is cleared between the commits of a `--range` (`Facts.clear_cache/0`), so long histories do not accumulate every revision's facts.
- Rules can declare `sources:`; `Rules.Message :no_fixup` applies to committed revisions only, so `fixup!` commits can be created locally and autosquashed. Subject-shape rules exempt git's own subjects (`Revert "…"`, `Merge …`) unless `exempt:` says otherwise.
- `assert_pure_move` compares both sides under the rename map: callers, aliases (including short aliases), tests, and docs updated for a module's new name are part of the move; any other change still fails. `defdelegate` is a public function in the facts and the API diff; functions in `@moduledoc false` modules are not API.
- Fewer false positives: `assert_routed` exempts `action_fallback` targets and any module a router names (custom route macros, `forward`); `assert_supervised` accepts a process that any other `lib/` module names (dynamic supervision); `EctoSchema.columns/1` skips `virtual: true` fields and honours `source:`; `assert_migrations_immutable(commit, since: "origin/main")` makes only published migrations immutable. `Commit` records its `repo`.
- Hooks step aside with a note while a merge is in progress, when amending a merge commit, and when `mix` is not on `PATH`; they pass `--on-error warn` so a crashed rule cannot block a commit; `mix presubmit.install` runs from the project directory (subdirectory projects get hooks that `cd` there) and refuses to install when `core.hooksPath` is set.
- `--on-error fail|warn` controls whether a rule that raises affects the exit status.
- Umbrella and subdirectory projects: every default directory pattern is anchored at any depth (`Presubmit.Paths`), dependencies are detected and compared across every `mix.exs`/`mix.lock` in the tree (`MixFile.all_deps/1`, `all_locked/1`), and a required file such as `CHANGELOG.md` counts at any project root.
- The user's git configuration is honoured (`safe.directory`, credentials, transports); plumbing calls pass the flags that keep their output configuration-independent. `Git.config/2`; the empty tree is derived from the repository's object format (no `/dev/null`).
- Robustness: modules without a literal name (`defmodule unquote(name)`, `defmodule __MODULE__.X`) are skipped instead of crashing extraction; submodule entries are ignored; files over `FileChange.max_diff_bytes/0` (1 MB) are not line-diffed (`diffed?: false`).
- `Presubmit.Commit.new/1` for synthetic change sets; explicit errors for merge commits and shallow clones.
- `Source.Facts.Function.api?/1`: `@doc false` functions are not API, so `public_api_diff/1`, `assert_api_changes_logged`, and `assert_removals_deprecated` ignore them.
- Fixture repositories as base trees plus `format-patch` scenarios under `fixtures/`.

### Removed

- ExUnit hosting (`use Presubmit`): rules run through `mix presubmit` instead, so the source is chosen per invocation and announced in the output.
